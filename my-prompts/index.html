Taskbar Sliders, version 3

Volume, brightness and blue-light sliders that sit right on the Windows 11 taskbar. Each knob is an icon that changes as you slide it.

Version 3. What's new: the percentage now shows in a tooltip that follows the knob and changes live as you move it, the numbers beside the sliders are gone, and the sliders sit closer together.

Already have the sliders? Paste this same prompt. It checks which version you have, tells you what the update will do, and changes only that. Your settings stay as they are.

  1. Copy the prompt with the button below.
  2. Open Claude Code on a Windows 11 computer and paste it in.
  3. Approve what it asks.

The sliders were built and tested on one Windows 11 computer with two external monitors. The prompt has not been run on other computers, and laptop screen support is untested, so your results may differ. The update steps were tried once on an old copy, as a dry run without starting the result. Read a prompt before you run it, because Claude Code will install and run this tool on your computer.

The prompt

SCREEN SLIDERS PROMPT, VERSION 3

START HERE: INSTALL OR UPDATE
Before you build or change anything, find out what I already have. Check %LOCALAPPDATA%\ScreenSliders\screen_sliders.pyw from outside Claude if you run inside the Claude desktop app (see that section below), because your own shell can show a copy that isn't really installed. The version is the line VERSION = "N" near the top of that file. If the file has no such line, it is version 2 if it contains the word IsPromoted, otherwise version 1.
- Not installed: this is a NEW INSTALL. Follow FULL BUILD below, and skip WHAT'S NEW.
- Same version as this prompt: tell me I'm up to date, change nothing, and stop.
- Newer than this prompt: tell me so, change nothing, and stop.
- Older than this prompt: this is an UPDATE. Follow these steps:
  1. Tell me first, in plain words, what this update will do: only the WHAT'S NEW entries newer than my version.
  2. Save my current script next to it as screen_sliders_v<N>.pyw. If that name is taken, add a number rather than overwriting it.
  3. Change only what those entries name. Do not rebuild or rewrite the rest. Keep my settings.json, Run value and shortcut as they are. FULL BUILD is there only so you can look up details, such as the TOOLTIP section.
  4. Set the VERSION line to this prompt's version.
  5. End the old copy, copy only the script over the old one, and start it again, from outside Claude if you run inside the Claude desktop app. Do not re-create the Run value or the shortcut.
  6. Run only the tests that the entries list, keeping to the care rules in test 12. Then tell me what changed, and that nothing else was touched.

WHAT'S NEW
Version 3 changes only these things since version 2:
- Removes the percentage numbers on the right of each slider.
- Brings the sliders closer: the window is now 385 wide, and the tracks run x=14 to 113, x=143 to 242 and x=272 to 371. The wheel's split points between sliders move to x=128 and x=257.
- Adds the live percentage tooltip. Build it exactly as the TOOLTIP section below says.
- Moves the colour sample to 4 px below the taskbar's top edge (scaled by DPI like everything else).
- Adds the VERSION line. Sets the top-level window's title to "ScreenSliders" if it isn't already.
- Tests for this update: 13 and 10, plus one click on each slider, reading the result back.

Version 2 changes these things since version 1:
- Adds the switch in Taskbar settings, with its hidden notification icon and its picture.
- Stops the flicker when the taskbar is clicked (the WinEvent hooks), and adds the mouse wheel while another app has the focus.
- Replaces PowerShell-style helpers with direct Core Audio and WMI calls, and adds the log, the shortcut and the install steps outside Claude.
- This one changed nearly the whole program, so an update from version 1 is the exception to "change only what's named": rebuild the script from FULL BUILD, keeping the floor and brightness from my settings.json. Version 1 stored "blue" as percent of blue KEPT, so set blue_removed to 100 minus that value. Run all the tests.

FULL BUILD

Build and install a small always-running tool for Windows 11: three sliders that sit directly on the Windows taskbar, just left of the tray icons. From left to right they control system volume, screen brightness and blue light. There are no text labels and no close button. A percentage appears in a tooltip only when the mouse is on a slider's knob or moving it. Each slider's moving knob is a small icon that changes as the value changes. The bar can be shown or hidden with its own switch in Windows Taskbar settings. Do all of it yourself, including installing it and testing it.

GROUND RULES
- Write it in Python 3 with tkinter, ctypes and the standard library only (json, threading, queue, winreg, zlib, struct and so on are fine). Add no pip packages. Do not build an unsigned .exe, because Windows Smart App Control can block it.
- Find a real Python install that has tkinter. Do not use a virtual environment's Python that belongs to another app (check for a pyvenv.cfg next to it); if you find one, use the base interpreter its "home" line points to. If no Python with tkinter exists, stop and ask me to install it from https://www.python.org/downloads/windows/ and then continue.
- No admin rights and no machine-wide changes. Do not change HKLM or any system setting.
- Install to %LOCALAPPDATA%\ScreenSliders\screen_sliders.pyw, with settings.json and a log file (screen_sliders.log, errors and the startup brightness reading only, kept under 256 KB) next to it.
- Start it with Windows through a value named ScreenSliders under HKCU\Software\Microsoft\Windows\CurrentVersion\Run, running pythonw.exe with the full script path.
- Also create %LOCALAPPDATA%\ScreenSliders\StartScreenSliders.lnk (pythonw.exe plus the quoted script path), so I can start it again with Win+R and that single path. Never ask me to paste a program-plus-arguments command line into Win+R or File Explorer; it fails there.
- Allow only one running copy, using a named mutex.
- Put the line VERSION = "3" near the top of the script. Updates of this prompt read it.
- settings.json holds floor (percent of blue kept at the far right), blue_removed (0 to 100 minus floor), bright (0 to 100) and tray_switch_set. It does not need to hold the volume, because Windows keeps that.

IF YOU RUN INSIDE THE CLAUDE DESKTOP APP (IMPORTANT)
- The Claude desktop app is a packaged (MSIX) app. Files your shell writes under %LOCALAPPDATA% or %APPDATA% that did not already exist, and values it writes under HKCU, can be silently redirected into %LOCALAPPDATA%\Packages\Claude_*\LocalCache\... and the package's private registry. Your shell sees a merged view, so everything looks installed, but my Explorer and Windows sign-in never see it.
- Processes you start from your shell are also ended whenever Claude updates or restarts.
- So do the install and every launch from outside Claude: through the real Explorer, get the desktop shell window with (New-Object -ComObject Shell.Application).Windows().FindWindowSW(..., 8 /*SWC_DESKTOP*/, ..., 1 /*SWFO_NEEDDISPATCH*/) and call .Document.Application.ShellExecute("powershell.exe", "-NoProfile -WindowStyle Hidden -EncodedCommand <base64>", "", "", 0). In PowerShell, FindWindowSW's by-reference arguments must be passed with [ref]. The final 0 hides the window; without it, Windows Terminal can take the focus for a moment. That PowerShell runs as a child of Explorer: let it copy the files from a staging folder that is real (check it is not under the package's LocalCache), write the Run value, create the shortcut, start pythonw.exe and write a short report file you can read back.
- Prove the real install with a report from a second PowerShell started the same way: the files, the Run value and the shortcut must all be listed there. A check from your own shell proves nothing, and that includes reading settings.json: your shell can see an older LocalCache copy of it. Leave any LocalCache copy alone; you don't need to delete it.

THE WINDOW
- Use a borderless Tk window (overrideredirect) titled "ScreenSliders", holding one Canvas that draws everything. Make the process per-monitor DPI aware.
- Get the real top-level handle with GetAncestor(winfo_id, GA_ROOT), add WS_EX_TOOLWINDOW and WS_EX_NOACTIVATE and remove WS_EX_APPWINDOW, so it has no taskbar button, no Alt-Tab entry and does not steal focus.
- Tk activates a window when it first maps it, even with WS_EX_NOACTIVATE set. Record the foreground window before creating Tk and give the focus straight back to it after setup, within 50 ms.
- Subclass the window procedures of the canvas and the top-level window: return MA_NOACTIVATE for WM_MOUSEACTIVATE, and take WM_MOUSEWHEEL there, because Tk only delivers the wheel to the window with keyboard focus, which this bar never has.
- Never call Tcl/Tk (after, after_idle, redraw) from inside a window procedure or a WinEvent callback; it crashes pythonw (0xc0000409). In those callbacks only queue data in a plain Python list or make Win32 calls. A 40 ms Tk timer processes the queued wheel steps.
- Every 400 ms: find Shell_TrayWnd and its child TrayNotifyWnd. Set the window's right edge 10 px left of the tray and centre it vertically on the taskbar. Call SetWindowPos with HWND_TOPMOST and SWP_NOACTIVATE.
- Clicking anything on the taskbar (for example the "Show hidden icons" ^ button) brings the taskbar in front and covers the bar, which looks like flicker if you only re-raise on the 400 ms timer. Use SetWinEventHook for EVENT_SYSTEM_FOREGROUND and EVENT_OBJECT_REORDER, limited to Explorer's process id (from Shell_TrayWnd) with WINEVENT_SKIPOWNPROCESS. In the callback, call SetWindowPos(HWND_TOPMOST, NOMOVE|NOSIZE|NOACTIVATE) at once, and keep doing it from the 40 ms timer for 0.6 seconds afterwards. Set up the hooks again when Explorer's process id changes.
- Hide the window with ShowWindow when either (a) a full-screen app is in front: the foreground window covers the taskbar's full width and reaches from the top of the screen to the bottom of the taskbar, and its class is not Progman, WorkerW, Shell_TrayWnd or Shell_SecondaryTrayWnd; or (b) the switch in Taskbar settings is off (see below). Show it again without activating it.
- About every 5 seconds, sample the screen colour with GetPixel, 6 px left of the window and 4 px below the taskbar's top edge (the very top row is a darker border, and another bar or an app icon can sit lower down in that spot), use it as the background so the bar blends in, and choose dark or light text and track colours by its luminance.

LAYOUT (pixels at 96 DPI; multiply everything by taskbar DPI / 96)
- Window: 385 wide, 40 high. There is no close button and no way to close it from the bar.
- Tracks are 99 long, 4 thick, with round caps. Volume runs x=14 to 113, brightness x=143 to 242, blue light x=272 to 371.
- No percentage text on the bar. See TOOLTIP.
- Each track is grey, with the part left of the knob filled in the slider's colour.
- Before drawing each knob icon, draw a disc of radius 12 in the background colour, so the track does not run through the icon.

TOOLTIP
- The percentage shows in a small separate window just above the taskbar: a borderless Tk Toplevel titled "ScreenSlidersTip" holding one label, white Segoe UI 12 px (pixel size, not points) on #2b2b2b, with padding 7 across and 3 down. Set its width and height once from the text "100%", so it doesn't jitter as the number changes.
- Give it the same no-focus treatment as the bar: WS_EX_TOOLWINDOW and WS_EX_NOACTIVATE, not WS_EX_APPWINDOW, and MA_NOACTIVATE in its window procedure. After setup, move it only with SetWindowPos (HWND_TOPMOST, SWP_NOACTIVATE) and show it only with ShowWindow(SW_SHOWNOACTIVATE). Never use Tk's deiconify for this, because it activates the window. Create it before giving the focus back at startup.
- It shows when (a) a slider is being dragged, (b) for 1.2 seconds after a wheel step on that slider, or (c) the pointer is inside the bar and within 12 px horizontally of a knob's centre. Otherwise it is hidden, including whenever the bar is hidden. Check this from the 40 ms timer using GetCursorPos and the window's rectangle. Do not rely on Tk's Enter and Leave events, which can be missed. Also update it straight away from press and drag.
- Its bottom edge sits 6 px above the taskbar's top edge, centred across on the knob, so it moves with the knob. The text is the slider's current value and changes live, including when something outside the app changes the volume. The blue slider shows the amount removed, the same number as before.

CONTROLS
- Pressing within 10 px of a track's ends jumps the knob there, and dragging moves it. Keep tracking while the button is held.
- Mouse wheel over a slider moves it by 2. "Over a slider" means nearest to it: the split points are x=128 and x=257. Wheel up always moves the knob to the right. The wheel must work while another app has the focus.
- Save settings on mouse release and after wheel moves.

SWITCH IN TASKBAR SETTINGS (Settings > Personalization > Taskbar > Other system tray icons)
- Windows only lists apps that own a notification-area icon there, so register one with Shell_NotifyIconW: uID 1, tooltip "Screen Sliders", and NIF_STATE with dwState = dwStateMask = NIS_HIDDEN. It is never drawn on the taskbar; it exists only to give the bar its switch. Add it again whenever the Shell_TrayWnd handle changes (Explorer restarted).
- Windows keeps the entry in HKCU\Control Panel\NotifyIconSettings\<number> with the values ExecutablePath, InitialTooltip, IsPromoted and IconSnapshot. Find ours by InitialTooltip = "Screen Sliders" and an ExecutablePath ending in pythonw.exe (it may use a {known-folder GUID}\... prefix).
- Read IsPromoted every 400 ms: 1 means the switch is on and the bar shows; 0 or missing means off and the bar hides. Until tray_switch_set is true, the entry may not exist yet, so keep the bar showing. The switch is an on/off toggle, not a radio button; apps cannot add their own controls to that page.
- New icons start switched off. The first time the entry exists, set IsPromoted = 1 so the bar stays visible, and save "tray_switch_set": true in settings.json so this happens only once.
- Windows labels the entry with the program file's name, so it shows as "Python". That cannot change without a separate .exe; say so in the report.
- The icon picture: build it in code (no image files) at the small-icon size (GetSystemMetrics SM_CXSMICON) as a 32-bit icon (CreateDIBSection + CreateIconIndirect). See-through background. On a 16 px grid: three white tracks 2 px thick from x=0.5 to 15.5 at y=3, 8 and 13; knobs at x=4.5, 11.5 and 7.3, radius 2.2, in the three slider colours (green, amber, blue), each on top of a white disc of radius 3.3, so it looks like a white ring. Colours are not premultiplied by alpha. Use 4x4 supersampling for smooth edges. Settings draws every app's icon on a rounded tile in the Windows accent colour, so the icon must stand out on a coloured tile.
- A hidden icon never refreshes the picture Windows stores, so the app writes its own icon as a 16x16 RGBA PNG (built with zlib and struct) into IconSnapshot whenever the stored bytes differ, checked about every 5 seconds.

SLIDER 1: VOLUME (colour #2e9e6b, 0 to 100%)
- Control the default playback device's master volume through Core Audio, calling the COM vtables directly with ctypes. CoCreateInstance CLSID BCDE0395-E52F-467C-8E3D-C4579291692E, IID A95664D2-9614-4F35-A746-DE8DB63617E6. Call GetDefaultAudioEndpoint (vtable slot 4) with eRender=0 and eConsole=0, then Activate (slot 3) with IID 5CDF2C82-841E-4546-9722-0CF74078229A.
- On that interface use slot 7 SetMasterVolumeLevelScalar, slot 9 GetMasterVolumeLevelScalar, slot 14 SetMute and slot 15 GetMute. Get the device fresh for each call so it follows a change of speakers. Release every COM pointer.
- Any change above 0 also turns mute off, like the Windows slider.
- About every 800 ms, unless this slider is being dragged, read the volume and mute state and redraw if they changed, so it follows the keyboard keys and the Windows volume panel.
- Icon: a filled speaker, with sound-wave arcs to its right, each 100 degrees wide and centred on the speaker's right edge. Radii are 5, 8, 11 and 14, 2 px thick. Show ceil(level x 4) arcs, so none at 0 and four at full.
- If the volume is 0 for any reason, or it is muted, replace the arcs with a small X. Dragging to 0 with the mouse must show the X too.

SLIDER 2: BRIGHTNESS (colour #e0a100, 0 to 100%)
- One slider sets all monitors together. On external monitors use DDC/CI through Dxva2: GetPhysicalMonitorsFromHMONITOR and SetVCPFeature with VCP code 0x10, retrying up to 3 times. Scale by the monitor's reported maximum.
- Monitors respond slowly, so send values from a helper thread that always sends only the newest value. The slider must never lag.
- On startup, read the current brightness with GetVCPFeatureAndVCPFeatureReply and show it. Do not change it on startup. A reply can be garbled when another program talks to the monitor at the same moment, so only trust a value that two reads in a row agree on (up to 4 reads), and log the value read. If monitors differ, show the first monitor that gives two agreeing reads.
- For a laptop's built-in screen, or a monitor that does not answer DDC/CI, fall back to WMI (WmiMonitorBrightness to read and WmiMonitorBrightnessMethods.WmiSetBrightness to set). Do this with WMI COM through ctypes, not PowerShell: IWbemLocator (CLSID 4590F811-1D3A-11D0-891F-00AA004B2E24, IID DC12A687-737F-11CF-884D-00AA004B2E24) ConnectServer slot 3, then CoSetProxyBlanket; IWbemServices GetObject slot 6, ExecQuery slot 20, ExecMethod slot 24; IEnumWbemClassObject Next slot 4; IWbemClassObject Get slot 4, Put slot 5, SpawnInstance slot 15, GetMethod slot 19. Pass BSTRs from SysAllocString. If neither works on a screen, tell me which screen in your final report.
- Icon: a filled sun of radius 4 with evenly spaced rays around it, starting 6.5 from the centre. Ray count is 4 x ceil(level x 4), meaning 0, 4, 8, 12 or 16, so at 0% there are no rays and the sun is always symmetrical. Rays get longer with level, ending at 9 + 3 x level. Use 2 px thick rays up to 10 rays and 1 px above that.

SLIDER 3: BLUE LIGHT (colour #2f7de1)
- The number shows how much blue is REMOVED. Far left shows 0% and the screen is normal. Sliding right removes more blue and makes the screen warmer.
- Use SetDeviceGammaRamp on a DC from CreateDCW for each monitor device. With b = fraction of blue kept, for i from 0 to 255 and v = i x 257: red = v, green = v x (1 - (1 - b) x 0.3), blue = v x b.
- Windows refuses strong ramps. On first run, try blue kept at 40% and go up in steps of 2 until a ramp is accepted, save that as the floor in settings.json, and use it as the far-right limit. If the floor is 50, far right shows 50%. Put the ramp back to normal after probing.
- Save the setting and reapply it on startup. Also reapply it about every 5 seconds whenever blue is being removed, but only if the current ramp (GetDeviceGammaRamp) differs, because Windows resets the ramp after sleep or a display change. Leave the ramp alone when the slider is at 0%, except to put it back to normal when I move the slider to 0.
- Icon: a light bulb. The glass is a circle of radius 6.5 centred 3 above the middle, with a tapered neck and two short lines for the base.
- Let level = position along the slider, 0 to 1. Blend the bulb's colour from pale #b9cde4 at level 0 to #2f7de1 at level 1, so it looks unlit on the left and fully on at the right.
- Add ceil(level x 9) rays fanning out from the top of the glass, spaced 27.5 degrees apart and centred straight up, from 8.5 to 10 + 2 x level from the glass centre, 2 px thick.

ROBUSTNESS
- Wrap every timer callback in try/except and log failures, so one error never stops the bar. Send Tk callback exceptions to the log too (pythonw has no console).
- On 64-bit Python, set argtypes and restype for every Win32 call that takes or returns a handle, or calls will fail with overflow errors or pass truncated handles.

TESTING (do this with the real mouse before you say it is done)
1. Install it (outside Claude, see above), start it, and confirm exactly one copy is running, the Run value is set, and the files are in the real folder, not in Claude's package storage.
2. Use SetCursorPos and mouse_event on the real sliders. Before every click, use WindowFromPoint to confirm the intended window is really what is under the pointer, and stop if not. Never assume a window came to the front: Settings and other windows often stay behind, and stray clicks then land in my other apps. Do not rely on counting windows or reading your own variables.
3. After each move, read the result back from the system: the monitors' brightness over DDC/CI, the gamma ramp with GetDeviceGammaRamp (allow a rounding difference of 2), and the volume and mute from Core Audio. Wait about 1.5 seconds after a brightness change before reading it back, so your read does not collide with the app's own DDC/CI writes.
4. Test both ends of the blue slider, the mouse wheel on all three sliders, and changing the volume and mute from outside the app to confirm the slider follows.
5. Test the wheel and clicks while another window has the focus (open some other window first), and confirm the bar never takes the focus, including at startup.
6. Drag volume to far left with the mouse and take a screenshot to confirm the X appears.
7. Click an empty part of the taskbar, and open and close the "Show hidden icons" ^ menu three times, sampling every 20 ms that the bar stays visible and on top (no flicker).
8. Open a full-screen window in front and confirm the bar hides, then shows again when it closes.
9. Open Settings > Personalization > Taskbar > Other system tray icons, find the entry with the sliders icon, flip its switch off and on with the mouse (the section starts collapsed, so click it open first, and use UI Automation to find the toggle's rectangle; Settings may open on another monitor), and confirm the bar hides and shows, IsPromoted changes, and no tray icon ever appears on the taskbar. Decode IconSnapshot and check it is the new picture.
10. Take a zoomed screenshot of the bar and fix anything overlapping or clipped. Also draw each icon at levels 0, 0.1, 0.25, 0.5, 0.75 and 1 in a separate temporary window using the same drawing code, and check how they look. Preview the tray icon on an accent-coloured tile too.
11. Measure the app's CPU use over 30 seconds and its memory.
12. Be careful with my settings. Record my volume, mute, brightness and blue values first, check that your reads returned real numbers before relying on them, put them all back exactly afterwards, keep test volumes low so nothing gets loud, and raise brightness by no more than 20 points during tests. If brightness is already near the top, lower it first and then raise it from there. Before any brightness wheel test, confirm the starting value the bar shows matches what the monitor reports.
13. Tooltip: with the real mouse, hold the pointer on each knob and confirm the tooltip shows, centred on the knob (within 2 px). Move off the knob along the track, and out of the bar, and confirm it hides. Drag the volume to three low values and confirm from zoomed screenshots that the tooltip moved each time and shows the matching number. Use the wheel on a knob and confirm it shows the new number. Confirm the focus never moved.

WHEN DONE
Tell me which version is now installed. Tell me plainly what passed, what failed and what you could not test. Mention these limits if they apply: some monitors do not support DDC/CI, HDR can stop the blue-light effect from working, and Windows Night Light can conflict with it. Tell me that the bar has no close button: to hide it I turn off its switch ("Python") in Taskbar settings, and to start it again I use Win+R with %LOCALAPPDATA%\ScreenSliders\StartScreenSliders.lnk. Also tell me how to remove it completely (end the pythonw.exe running screen_sliders.pyw, delete the ScreenSliders Run value, and delete the %LOCALAPPDATA%\ScreenSliders folder).

Read Aloud Bar, version 1

Highlight text in any app, press play on the Windows 11 taskbar, and your computer reads it out loud. It has a pause button and a sound bar you can click to jump around. No API key, no account, no internet and no .exe.

It uses the voices already built into Windows, so it sounds more robotic than paid voice services.

This matters more than in most tools: the app holding my highlighted text must stay in front, or the copy gets nothing.
- Tk activates a window when it first maps it, even with WS_EX_NOACTIVATE set. Record the foreground window before creating Tk and give the focus straight back to it after setup, within 50 ms.
- Subclass the window procedures of the canvas and the top-level window: return MA_NOACTIVATE for WM_MOUSEACTIVATE, and catch WM_HOTKEY there.
- Never call Tcl/Tk (after, after_idle, redraw) from inside a window procedure or a WinEvent callback; it crashes pythonw (0xc0000409). In those callbacks only queue data in a plain Python list or make Win32 calls. A 40 ms Tk timer processes what was queued.
- Every 400 ms: find Shell_TrayWnd and its child TrayNotifyWnd. If a visible top-level window titled "ScreenSliders" exists (my taskbar sliders tool), set the bar's right edge 8 px left of that window; otherwise 8 px left of the tray. Centre it vertically on the taskbar. Call SetWindowPos with HWND_TOPMOST and SWP_NOACTIVATE.
- Clicking anything on the taskbar brings the taskbar in front and covers the bar, and a press in that moment would miss. Use SetWinEventHook for EVENT_SYSTEM_FOREGROUND and EVENT_OBJECT_REORDER, limited to Explorer's process id (from Shell_TrayWnd) with WINEVENT_SKIPOWNPROCESS. In the callback, call SetWindowPos(HWND_TOPMOST, NOMOVE|NOSIZE|NOACTIVATE) at once, and keep doing it from the 40 ms timer for 0.6 seconds afterwards. Set up the hooks again when Explorer's process id changes.
- Hide the window with ShowWindow when a full-screen app is in front: the foreground window covers the taskbar's full width and reaches from the top of the screen to the bottom of the taskbar, and its class is not Progman, WorkerW, Shell_TrayWnd or Shell_SecondaryTrayWnd. Show it again without activating it.
- About every 5 seconds, sample the taskbar's colour with GetPixel, 6 px left of the window and 4 px below the taskbar's top edge (the very top row is a darker border, and another bar or an app icon can sit lower down in that spot). The match can be a shade or two off on the Windows 11 taskbar, which is fine. Use it as the canvas background so the bar looks see-through, and redraw if it changed.
- About every 30 seconds read SystemUsesLightTheme from HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize. 0 means a dark taskbar, anything else light. nativeTheme-style app settings are the wrong signal; the taskbar is themed separately.

LAYOUT (pixels at 96 DPI; multiply everything by taskbar DPI / 96)
- Window: 228 wide, 38 high. Left to right: 6 padding, play button 28 x 28, 6 gap, sound bar filling the middle, 6 gap, cog 28 x 28, 6 padding. Both buttons are centred vertically.
- Colours on a light taskbar: button #8B5A2B, button hover #9C6733, cog #A6A6A6, cog hover #6B4423, unplayed sound bars #1a1206 at 30% over the background, text #1a1206.
- Colours on a dark taskbar: button and hover the same, cog #BDBDBD, cog hover #C8935A, unplayed bars white at 28% over the background, text #E8DCC8.
- Tk canvas shapes have jagged edges, so draw the play, pause and cog icons in Python at 4 x 4 supersampling, blend them with the current background colour, turn them into an in-memory PNG (zlib and struct) and show them with tk.PhotoImage(data=base64). Cache one image per icon, colour and background. Do not use image files.
- Play button: a brown rounded square, corner radius 9, with a rounded right-pointing triangle cut out of it, so the taskbar colour shows through the arrow. On the 28 grid the triangle's points are about (10.5, 8.5), (19, 14) and (10.5, 19.5), with corners rounded by about 1.
- Pause icon: the same rounded square with two bars cut out, x=10 to 13 and x=15 to 18, y=9 to 19, corners rounded by 1. Show it only while playing.
- Cog: a solid gear 20 x 20, centred in its 28 x 28 area, with 8 teeth and a round hole in the middle (hole radius about 3.6 of a 24-unit gear). The cog's colour changes on hover, and it also gets a faint rounded background: #1a1206 at 10% on light, white at 12% on dark.
- Sound bar: 30 bars, each 3 wide with rounded ends, evenly spaced across the middle area. It is always shown and never changes shape. For bar i from 0 to 29: h = 0.5 + 0.28 x sin(i x 0.9 + 0.91) + 0.2 x sin(i x 0.37 + 0.287), limited to 0.12 to 1, and the bar's height is h x 26, at least 3, centred vertically.
- The first round(fraction x 30) bars are filled in the button colour, where fraction is how far through the text it has read. The rest are the unplayed colour. When nothing is playing or paused, none are filled.
- A short message ("Highlight text first") replaces the sound bar for 2.8 seconds, centred, Segoe UI 12 px (pixel size, not points), then the bars come back.
- The whole button area and the whole sound bar area take clicks, including the gaps between bars and the cut-out arrow.

SPEECH: WINDOWS BUILT-IN VOICES THROUGH SAPI, CALLED WITH CTYPES
- Call CoInitialize on the main thread and keep the voice on the main thread only. CoCreateInstance CLSID 96749377-3391-11D2-9EE3-00C04F797396, IID 6C44DF74-72B9-4992-A1EC-EF996E0422D4 (ISpVoice), and call its COM vtable directly with ctypes.
- ISpVoice slots: SetVoice 18, Speak 20, GetStatus 22, SetRate 28, SetVolume 30. Speak flags for every call are SPF_ASYNC | SPF_PURGEBEFORESPEAK | SPF_IS_NOT_XML = 1 | 2 | 0x10. Passing an empty string with these flags stops the speech.
- GetStatus fills this struct: ulCurrentStream, ulLastStreamQueued (ULONG), hrLastResult (HRESULT), dwRunningState (DWORD), ulInputWordPos, ulInputWordLen, ulInputSentPos, ulInputSentLen (ULONG), lBookmarkId (LONG), PhonemeId (WCHAR), VisemeId (int), dwReserved1, dwReserved2 (DWORD). dwRunningState 1 means done, 2 means speaking. ulInputWordPos is where it is in the string given to the last Speak, in UTF-16 units, and returns to 0 when speech is stopped.
- Find voices in the registry under both HKLM\SOFTWARE\Microsoft\Speech_OneCore\Voices\Tokens and HKLM\SOFTWARE\Microsoft\Speech\Voices\Tokens. The OneCore ones sound better, and many are not listed by SAPI's default voice list, so select them by creating the token yourself: CoCreateInstance CLSID EF411752-3736-4CB4-9C8C-8EF4CCB58EFE, IID 14056589-E16C-11D2-BB90-00C04F8EE6C0 (ISpObjectToken); slot 15 is SetId(NULL, "HKEY_LOCAL_MACHINE\SOFTWARE\...\Tokens\<name>", FALSE). Then pass it to SetVoice and release it.
- Each token key's default value is the display name and its Attributes subkey has a Language value (hex LCID). List one entry per voice name, preferring OneCore over Desktop. Default voice: the first OneCore voice whose language matches GetUserDefaultUILanguage, preferring one named Mark, then any voice of that language, then the first voice.
- If no voice can be created, say so in the bar's message and log it.
- PAUSE WITHOUT SAPI's PAUSE. Do not use ISpVoice Pause and Resume: measured on Windows 11, the sound carries on for about 0.9 seconds after Pause, and the calls are counted. Instead, to pause: read ulInputWordPos, add it to the offset of the string last spoken, save that as the resume point, then Speak "" to stop (the sound stops within 0.1 seconds). To resume: Speak the text from the resume point.
- A 200 ms timer reads GetStatus while playing and sets fraction = (offset + ulInputWordPos) / text length, in UTF-16 units. It treats running state 1 as finished only once 0.5 seconds have passed since the last Speak, because the state can read wrong right after one.

READING THE HIGHLIGHTED TEXT
- The tool gets the selection by copying it, because most apps offer no other way, so it has to look after my clipboard. Do this on a helper thread and hand the result back through a queue to the 40 ms timer, so the bar never freezes.
- Steps: wait until Ctrl, Alt, Shift and Win are released (GetAsyncKeyState, at most 1 second). Note GetClipboardSequenceNumber. Read the current clipboard text if it holds CF_UNICODETEXT. Send Ctrl+C with SendInput. Wait for the sequence number to change, up to 1.5 seconds, or 0.7 seconds when resuming from a pause. If it changed, read the new text, retrying if another app has the clipboard open.
- Do not clear the clipboard first: an app that ignores the copy would leave me with an empty clipboard. If it never changed, nothing was highlighted.
- After reading, put my previous clipboard text back if there was any.
- Set argtypes and restype on GlobalAlloc, GlobalLock, GlobalUnlock, GetClipboardData and SetClipboardData, or 64-bit handles get truncated.
- Change \r\n to \n and trim the text before comparing or reading it.

CONTROLS
- Phases: idle, loading, playing, paused, done. Loading is only the moment while copying; the bars pulse gently and presses are ignored.
- Press play while playing: pause. It does not look at the selection.
- Press play otherwise: get the selection. New highlighted text wins and reads from the start, even when paused. If the selection is the same text as last time, or there is none: resume when paused, read again from the start when done. If it is the same text and the phase is idle, read it. If there is no text and nothing to resume, show "Highlight text first".
- Click the sound bar: fraction = click position across the bar area. Move to the nearest word start, and read from there, whether it was playing, paused or done. If nothing has been read yet, show "Highlight text first". The click never touches the clipboard.
- Keyboard shortcut: Ctrl+Alt+R does the same as pressing play. Use RegisterHotKey on the top-level window and catch WM_HOTKEY in the window procedure. It is stored in settings.json as "hotkey", for example "ctrl+alt+r", and can be changed there. If Windows refuses it because another app holds it, log it and show that in the settings window, and keep working otherwise.
- Cog: opens a normal small settings window, centred on the screen. This one may take focus. It has a list of voices, a speed slider from -5 to +5 (SetRate, default 0), a volume slider from 0 to 100 (SetVolume, default 100; this is the voice's volume, not the system's), a Test button that reads one short sentence, a line showing the shortcut, and a "Close the bar" button that ends the program. A second press on the cog brings the open window to the front; it never opens two.
- Save settings on every change. settings.json is read at startup only, so restart the bar after editing it by hand. Nothing is read aloud at startup.

ROBUSTNESS
- Wrap every timer callback in try/except and log failures, so one error never stops the bar. Send Tk callback exceptions to the log too (pythonw has no console).
- On 64-bit Python, set argtypes and restype for every Win32 call that takes or returns a handle, or calls will fail with overflow errors or pass truncated handles.
- Stop speaking and release COM pointers when the program ends.
